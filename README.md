# Плод — сортировка фруктов

Готовый проект для Streamlit Community Cloud. Приложение определяет вид фрукта, оценивает внешнее качество и при необходимости отмечает найденные участки на яблоках. Поддерживаются яблоки, бананы и лаймы.

## Быстрое размещение

Понадобятся аккаунты GitHub и Streamlit Community Cloud. Загрузка выполняется через браузер.

1. Распакуйте архив и откройте папку `fruit_streamlit`.
2. На GitHub создайте репозиторий, например `fruit-sorting`. Для простого открытого учебного проекта можно выбрать Public.
3. В репозитории выберите **Add file → Upload files**. Перетащите содержимое папки `fruit_streamlit` в область загрузки. Сохраните структуру папок. Зафиксируйте загрузку кнопкой **Commit changes**.
4. Проверьте корень репозитория. В нём должны находиться `streamlit_app.py`, `inference.py`, `requirements.txt`, `README.md` и папки `models`, `config`, `examples`, `.streamlit`. В `models` должны находиться `sorting.onnx` и `apple_regions.onnx`.
5. Откройте https://share.streamlit.io и войдите с привязкой GitHub.
6. Нажмите **Create app**, затем **Yup, I have an app**.
7. Укажите созданный репозиторий, ветку `main` и главный файл `streamlit_app.py`.
8. В **Advanced settings** выберите **Python 3.12**, сохраните настройки и нажмите **Deploy**.
9. После установки библиотек откройте приложение и нажмите **Проверить 12 примеров**.

Если содержимое проекта было загружено целиком во вложенную папку `fruit_streamlit`, путь главного файла будет `fruit_streamlit/streamlit_app.py`. Рекомендуется разместить содержимое проекта в корне, чтобы настройки `.streamlit/config.toml` применялись непосредственно.

Размер каждого файла модели меньше 25 МБ, поэтому их можно загрузить через обычную веб-форму GitHub. Загрузка одного архива ZIP в репозиторий не разворачивает приложение.

Официальная инструкция размещения — https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy

Описание установки зависимостей — https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/app-dependencies

## Локальный запуск

Рекомендуется Python 3.12. Откройте терминал в папке проекта и выполните последовательно.

```bash
python -m pip install -r requirements.txt
python -m streamlit run streamlit_app.py
```

Откройте адрес, указанный в терминале. Обычно это http://localhost:8501. Для остановки нажмите Ctrl+C в терминале.

## Возможности

- Загрузка партии из 1–20 фотографий JPG, PNG или WebP.
- Обычная сортировка с решением для каждой фотографии.
- Контроль партии с направлением до 10% фотографий на ручную проверку.
- Дополнительный поиск участков на яблоках.
- Просмотр решений, оценок и найденных рамок.
- Отбор результатов по решению.
- Скачивание таблицы CSV для Excel.
- Двенадцать встроенных фотографий и справка в боковой панели.

## Работа с приложением

В левой части добавьте свои фотографии или выберите отдельные примеры. Общий размер партии ограничен 50 МБ, каждой фотографии — 10 МБ. Снимки с разрешением больше 24 миллионов точек отклоняются, чтобы ограничить расход памяти.

Выберите режим. В обычной сортировке применяется граница оценки дефекта 50%. В контроле партии используются три варианта яркости и сохранённая исследовательская граница 3%. Для партии из 1–9 фотографий квота ручной проверки равна нулю, из 10–19 фотографий — одному изображению, из 20 — двум изображениям.

Кнопка **Проверить фотографии** обрабатывает загруженные файлы и выбранные примеры вместе. Кнопка **Проверить 12 примеров** обрабатывает готовую партию из набора. Для этой кнопки также применяются выбранный режим и настройка поиска участков.

Результат появляется справа. Фильтр **Показать результаты** позволяет оставить фотографии с нужным решением. Кнопка скачивания сохраняет всю обработанную партию, независимо от выбранного фильтра.

Оценка дефекта не является измерением доли повреждённой поверхности. Рамки на яблоках показываются отдельно и не изменяют решение о качестве. Номера рамок 0 и 1 сохраняют исходную разметку набора, предметное значение этих номеров не подтверждено.

Приложение хранит загруженные файлы в памяти текущего сеанса и не записывает их на диск. После обработки в результате сохраняются уменьшенные изображения. Модели совместно используются разными посетителями. Во время обработки одной партии второй посетитель получает сообщение о занятой системе. Скачивание таблицы и смена фильтра сохраняют уже полученные результаты.

## Подготовка моделей для Community Cloud

Включены две модели в формате ONNX. Они получены преобразованием обученных моделей исходного проекта. Для выполнения используется ONNX Runtime на центральном процессоре. Загрузка моделей выполняется при первом запросе и сохраняется в общем ресурсе Streamlit. Модель участков загружается при включении дополнительного поиска.

Числовые параметры и правила сортировки сохранены. В `config/conversion_check.json` записаны результаты сравнения исходного и нового выполнения на 12 встроенных фотографиях и шести вариантах изображений для обнаружения. В обоих режимах совпали решения и виды фруктов. В проверке обнаружения совпали категории и число участков. Небольшие различия числовых оценок обусловлены выполнением вычислений.

Эта проверка подтверждает перенос на проверенных примерах. Она не является повторной оценкой качества на всём контрольном наборе. Исходные показатели исследования приведены в справке приложения как результаты ранее выполненного эксперимента.

## Ограничения исследования

Оценка качества относится к фотографии целиком. На ней может быть несколько плодов. Для неизвестного предмета также может быть получен ответ одного из трёх поддерживаемых видов. Поиск неизвестных объектов отдельно не обучался.

Модель участков проверена на яблоках с тёмным фоном. Для бытовой съёмки на другом фоне результат может отличаться. Внутренние повреждения, химический состав и пригодность к употреблению не оцениваются.

При исследовании не был установлен дополнительный эффект индивидуальных границ и изменчивости ответа. В сохранённых настройках все границы равны 3%, вес изменчивости равен нулю. Ручная проверка оценивается отдельно, её результат не моделируется.

Площадка Community Cloud ограничивает вычислительные ресурсы и может останавливать неактивное приложение. Первый запрос после остановки включает повторную загрузку моделей в память. Успешная местная проверка не гарантирует доступность конкретной квоты площадки для каждого аккаунта.
